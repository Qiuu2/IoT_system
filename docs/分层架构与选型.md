# 分层架构与开源选型

> 可视化版本：https://claude.ai/code/artifact/02639ff3-d585-47eb-83da-c5ecb3719202
> Star 数与许可证于 2026-09-04 逐个核实于各项目 GitHub 仓库页。

## 处置结论：9 层中只有 3 层要真正自研

| 层 | 职责 | 处置 | 硬件未到能否开工 |
|---|---|---|---|
| L1 设备接入驱动层 | 私有指令编解码、在线检测 | **自研** | 需先写设备模拟器 |
| L2 协议运行时 | 连接管理、会话保活、指令通道 | **改造 JetLinks** | 需模拟器 |
| L3 控制与场景编排 | 场景预案、上电时序、联动 | **自研** | 可 |
| L4 空间与会务预约 | 空间树、预约冲突、日程甘特 | **自研** | 可 |
| L5 运维业务层 | 告警、工单、巡检、资产、报表 | 改造 RuoYi | 可 |
| L6 数据与存储 | 关系库、时序库、消息 | 直接用（选型有雷） | 可 |
| L7 可视化前端 | 后台框架、图表、组态、拓扑 | 直接用 | 可 |
| L8 平台基础与集成 | 用户/部门/角色/字典、三方对接 | 直接用 | 可 |
| L9 AI 能力（选配） | AI 速记 | 直接用 | 可 |

自研的 3 层（L1/L3/L4）恰好是产品差异点，本来就不该外包给开源。

## 许可证红线

1. **EMQX 已转 BSL 1.1** — 网上绝大多数资料仍写 Apache-2.0。按旧资料选型会在交付时才发现要买授权。
2. **unitedrhino/things 口径冲突** — 仓库标 AGPL-3.0，README 写 Apache-2.0，法务审查无法过关。
3. **FastBee / Snipe-IT 是 AGPL-3.0** — 传染范围含「通过网络提供服务」，私有部署给医院同样触发。这两个是各自领域做得最好的，越好越容易忍不住抄。
4. **TDengine 是 AGPL-3.0** — 以本项目数据量，TimescaleDB 甚至纯 PostgreSQL 就够。

## 硬件未到时的落地顺序

1. **先写设备模拟器** — 按清单协议参数造假设备（TCP 监听进程，模拟 RS6608 串口透传、REL08-1U 的 Modbus-TCP 寄存器、PNC218 定时回传电压电流）。做完这步 L1–L3 全部可脱离硬件开发，模拟器后期直接变成自动化测试的桩。
2. **并行推 L8 + L5** — 拉起 RuoYi 底座跑通用户/部门/角色/字典，再做告警、工单、资产、巡检。零硬件耦合，最出进度。
3. **做 L4 空间与预约** — 同样零硬件依赖，且需求条目最密集。空间树数据模型要一次设计对，17 个空间会长成上百个节点。
4. **补 L1 真实驱动** — 唯一阻塞项是拿到指令码表。**现在就该向 EMeta 或设备厂商索要通讯协议文档**，前置时间往往比预期长。
5. **最后定 L6 热备** — 总平台↔分平台 `<1.2s` 切换是清单技术难度最高的单项（对应竞品 ¥9,000 模块）。建议先用单平台跑通全部功能，热备作为独立课题推进。
