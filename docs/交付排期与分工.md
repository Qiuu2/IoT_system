## 结论先行

按下方拆分估算约 **342–535 人日**，三人满负荷折合 **5.7–8.9 个月**。
下面的 26 周排期对应乐观值，且假设三人全程满负荷、无并行项目。

估算里最大的变数——13 个子系统对接（65–130 人日）——**工期不由团队决定**，
取决于各厂商接口文档何时到位。

## 一、三人分工

按**技术栈边界**切，不按功能模块切。功能模块切法会让三个人天天在同一批文件上打架。

| | 角色 | 技术栈 | 负责 |
|---|---|---|---|
| **甲** | 后端底座与业务域 | Java / Spring Boot、数据建模、工作流 | 数据模型与 API 契约、空间树、设备台账、二维码、组织 RBAC、系统日志、工单、维保、巡检、消息中心、告警聚合、业务报表 |
| **乙** | 接入域与部署 | 协议 / 网络、Netty 或 Go、运维 | 协议适配框架、设备模拟器与驱动、**13 个子系统对接**、视频接入（Onvif/GB28182）、三网部署、服务器上架、等保整改 |
| **丙** | 前端与移动端 | Vue3 / Element Plus、uni-app 或 Flutter | 前端脚手架与 UI 规范、Web 后台全部页面、移动 APP、综合态势首页、视频点位图、大屏 |

**丙最容易超载**——Web 后台 + APP + 态势大屏是三件事。
对策：Web 后台的增删改查页面全部用代码生成器出（RuoYi 系自带），丙的精力保住 APP 与态势页。
若中期顶不住，第一个该加人的位置是丙。

## 二、六个阶段

### P0 决策与冻结（第 1–2 周 · 全员）

**干什么**：敲定三网部署方案；确认信创深度与等保定级；冻结二维码编码规则；
建立 13 个厂商接口文档的催收台账；技术选型定稿、环境就绪。

**交付物**：《部署架构决策书》（含三网数据流向图）、《技术选型说明》（含信创合规说明）、
《二维码编码规范》、《接口文档催收台账》（13 项，含责任人与承诺日期）、代码仓与 CI 与三套环境。

> **不做完不许进 P1。** 三网方案没定就动手等于赌架构，赌输了所有代码的部署形态都要重来。

### P1 底座与契约（第 3–6 周）

**干什么**：甲做数据模型定稿、空间树、设备台账、二维码、组织 RBAC、系统日志；
乙做协议适配框架骨架、模拟器扩展到医院场景（BA、照明、能耗、门禁）；
丙做前端脚手架、UI 规范、组件库、台账与空间管理页。

**交付物**：**API 契约文档（OpenAPI）**——全队后续唯一事实源；数据库设计说明书与建表脚本；
可运行的底座（登录、组织、权限、空间树、台账、扫码查询）；设备模拟器；前端 UI 规范与组件库。

> 完全不依赖硬件与厂商，最该抢时间。P1 产出决定后面三人能否真正并行。

### P2 接入层（第 5–22 周 · 滚动）

**干什么**：标准协议先行（Modbus/BACnet/OPC/串口，不依赖厂商文档）；视频标准流接入；
13 个子系统**按文档到位顺序滚动对接，不等齐再开始**；会议中控驱动；点位归一与可写点权限。

**交付物**：协议适配框架与驱动开发规范；每个子系统一份《对接说明》（协议、点表、读写边界、
验证记录）；点位总表；基于模拟器的接入层自动化测试。

> **工期不可控。** 建议对甲方按「已对接 N/13」报进度，周报固定披露未到位的接口文档清单，
> 把风险显性化而不是自己扛。

### P3 业务线（第 7–16 周）

**干什么**：报修工单（流程引擎、派单、流转、权限）；维保（模板、计划、任务生成、班组、外委）；
巡检（设备/设备间两类、三种巡检点类型、排班、离线）；消息中心；**告警聚合**；报表与模板化导出。

**交付物**：三条业务线端到端跑通（Web 端）；告警→工单→处理→回填闭环演示；
报表模板配置能力；业务测试用例集。

> 不依赖硬件，用 P1 的模拟器造告警即可全流程验证。三人中工作量最大的一块。

### P4 移动端（第 15–21 周）

**干什么**：首页（任务、通知、报警、主动推送）；扫码查台账与记录；执行巡检与维保任务；
**离线提交**；报修下单与接单。

**交付物**：APP 安装包（Android/iOS）与分发方案；离线数据同步机制说明与冲突处理规则；
推送通道打通（含医院网络下的可达性验证）。

> **提前踩点**：推送在医院内网能否出网、iOS 走企业签还是 TestFlight。
> 这两件事拖起来能拖掉几周，建议 P1 就探明。

### P5 融合与呈现（第 19–24 周）

**干什么**：综合态势首页（按角色呈现）；视频点位图；数视融合（大屏播放、分屏、报警闪烁）；
大屏渲染。

**交付物**：综合态势页与视频点位图；大屏方案与现场调试记录；报警联动演示。

> **必须排最后。** 态势页依赖所有数据源就位，提前做会反复返工——每接一个子系统就改一次首页。

### P6 现场联调与交付（第 21–26 周 · 全员）

**干什么**：服务器上架、部署、三网连通性验证；真实设备替换模拟器逐系统联调；
等保测评整改；压力与稳定性测试；用户培训与文档移交。

**交付物**：验收测试报告（逐条对应清单 427–433）；部署运维手册、用户手册、培训记录；
等保测评通过证明；源码与数据库脚本与第三方接口资料归档；3 年质保的响应机制与值班安排。

> 验收报告要逐条对应清单行号。PRD 里每条需求都标了溯源行号就是为了这一刻。

## 三、工作量估算

粗估，用于判断人力是否够，**不作为报价依据**。
假设：复用成熟后台框架（RuoYi 系）、增删改查页面走代码生成、单个子系统对接按中位数计。

| 工作块 | 负责 | 乐观 | 悲观 | 主要变数 |
|---|---|---:|---:|---|
| P0 决策与冻结 | 全员 | 15 | 25 | 甲方决策速度 |
| 底座：模型 / 台账 / 权限 | 甲 | 30 | 40 | 数据模型是否一次做对 |
| 业务线：工单/维保/巡检/消息/报表 | 甲 | 55 | 75 | 流程引擎可配置深度 |
| 协议框架 + 模拟器 + 会议中控 | 乙 | 25 | 35 | 协议种类多少 |
| **13 个子系统对接** | 乙 | 65 | 130 | **文档质量与厂商配合度** |
| 视频接入与融合 | 乙 | 20 | 35 | 是否有私有流协议 |
| Web 前端全量页面 | 丙 | 40 | 55 | 代码生成器覆盖率 |
| 移动 APP | 丙 | 30 | 45 | 离线同步复杂度 |
| 综合态势 + 大屏 | 丙 | 22 | 35 | 视觉要求高低 |
| 部署/等保/测试/培训/文档 | 全员 | 40 | 60 | 等保定级与整改量 |
| **合计（人日）** | | **342** | **535** | 三人折合 5.7–8.9 个月 |

## 四、工期压不下来时的三个杠杆

| 杠杆 | 做法 | 代价 |
|---|---|---|
| **分批验收**（最推荐） | 第一批交底座 + 三条业务线 + 已到位的子系统；第二批补齐剩余对接与态势大屏 | 需甲方同意分期，合同相应拆分 |
| **缩减首批对接范围** | 13 个系统按价值排序，先接视频、能耗、照明、BA、会议；医用气体、物流传输后置 | 需甲方书面确认优先级 |
| **加人，加在丙** | Web + APP + 大屏本就是三件事，前端最容易切给第四人 | 成本增加；甲乙位置加人收益小 |

**不建议动的地方**：砍掉 P0 直接开工、把等保整改留到最后一周、让态势大屏提前到 P3。
这三件看起来省时间，实际都是把风险推到最不能承受的时点。
