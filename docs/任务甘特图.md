# 三人任务甘特图

> 可视化版本：https://claude.ai/code/artifact/0e9f09d8-1eb3-413f-bbf4-864271c6a53a
> 配套 [交付排期与分工](./交付排期与分工.md)（阶段级）与 [PRD](./PRD.md)

一个任务一行。里程碑对应四步验收法：有什么 → 好不好 → 坏了怎么办 → 平时怎么管。

## 里程碑

| 里程碑 | 周 | 对应哪一步 | 怎么验 |
|---|---|---|---|
| M1 契约冻结 | W2 | — | 接口文档发出、甲给丙的假接口能跑、13 家厂商文档催收台账建立 |
| M2 台账可用 | W8 | 这栋楼里有什么 | 打印一个二维码，手机扫出设备信息 |
| M3 数据是活的 | W14 | 它们现在好不好 | 当场拔掉一台设备网线，一分钟内页面变离线 |
| M4 闭环跑通 | W20 | 坏了怎么办 | 造故障：告警 → 工单 → 手机接单 → 关闭 |
| M5 现场可用 | W24 | 平时怎么管 | 信号差的机房完成一次巡检，回来自动上传 |
| M6 验收 | W26 | — | 逐条对照招标清单 427–433，等保测评通过 |

## 三条要盯住的线

**两处关键交接**
- **W4 甲 → 丙**：接口文档和假接口。给不出来，丙从第 5 周起空转。
- **W5 乙 → 甲**：模拟设备数据。给不出来，甲的「收数据」写不下去。

**斜纹段不由团队决定**
乙的「13 个厂商系统滚动对接」横跨 W5–W22，取决于各厂商何时给接口文档。
文档晚到，这段整体右移，M4 和 M6 跟着顺延。这是要向甲方交代的头号风险。

**三件事必须排最后**
大屏（W22）、等保整改（W21）、现场联调（W20）。提前做大屏会反复返工，
因为每接一个新子系统首页就得改一次。
