## 一、清单告诉我们的事

这份清单不是软件功能清单，是一份 **AV 工程 BOM + 招标技术要求**，品牌方案为 EMeta。
但它的"主要技术参数"列里写满了软件验收条款——**192 条**运维平台功能 + **63 条**会务系统功能，
已抽取到 [`需求规格-自清单还原.md`](./需求规格-自清单还原.md)。这就是缺失的 PRD。

### 1.3 关键结论：这不是 MQTT 物联网，是 AV 中控

清单里的受控设备与接入方式：

| 设备 | 型号 | 接入协议 | 对应截图 |
|---|---|---|---|
| 插卡中控主机 | EMeta-WL5000 | TCP/UDP/telnet/HTTP/MQTT/SNMP/RS232/RS485/红外 | 主机管理 |
| 中控核心板 | EMeta-WL5000-CORE | 2×RS232 + 2×RS485 + 2×千兆网口 | 主机状态 |
| **八串口服务器** | EMeta-RS6608 | TCP Server/Client、UDP、类 RFC2217，8~12 路 RS232/485/422 | "分布式232口测试" |
| 网络八路红外扩展器 | EMeta-IR-8RJ45 | TCP/UDP 调取红外码，内存 200 组红外数据 | — |
| 8 路网络继电器 | EMeta-REL08-1U | TCP / UDP / **Modbus-TCP** / MQTT / HTTP | 灯光、窗帘、幕布 |
| 21 路智能时序电源 | EMeta-PNC218 | RS232（2400–38400,8N1）+ 网络，**上传电压电流** | 告警统计"电源时序器（能源版）" |
| 8 路网络时序电源 | EC-PNC809 | TCP/UDP（TCP Server/Client 均可） | 同上 |
| HDMI 无缝矩阵 | EMeta-JZ-M0808S | 私有 TCP/串口指令 | "会议室矩阵" |
| 数字会议主机 | EM-PM-CHM9 | 私有 | "数字会议主机" |

**没有一台设备走标准物模型。** 全是 TCP/串口 + 厂商私有 ASCII/HEX 指令串。
这解释了截图里为什么用 `PING 检测 + 协议端口 + 编码类型(ASCII)` 来描述设备——那是中控的设备表，不是 IoT 物模型表。

**能耗管理的数据源**就是时序电源上传的电压电流，不需要额外电表。

## 二、选型结论

### 2.1 一句话

> **没有任何一个开源项目能覆盖这份清单。** 通用 IoT 平台解决的是"海量设备上报遥测"，
> 而这套系统是"少量设备、强控制、强场景、私有指令下发"。两者内核相反。
> 正确做法是：**拿开源做业务外壳，中控驱动层自研。**

### 2.2 推荐组合

| 层 | 选型 | Star | License | 理由 |
|---|---|---|---|---|
| 业务外壳<br>(用户/部门/角色/字典/工单/审批/多租户) | [YunaiV/ruoyi-vue-pro](https://github.com/YunaiV/ruoyi-vue-pro) | 39.1k | **MIT** ✅ | 清单第 16–18 条（部门树形无限级、角色权限合集、用户管理）就是 RuoYi 的原生功能，逐字对得上。Vue3 + Element Plus 暗色主题与截图一致 |
| 设备接入/协议解析 | [jetlinks/jetlinks-community](https://github.com/jetlinks/jetlinks-community) | 6.6k | **Apache-2.0** ✅ | 唯一把"自定义 TCP 协议包(ProtocolSupport)"做成一等公民的国产平台，正好写 EMeta 私有指令解码器 |
| 场景编排 | [node-red/node-red](https://github.com/node-red/node-red) | 23.6k | **Apache-2.0** ✅ | 可选。"一键全开/全关""会议开始联动"用流程图配置比硬编码好维护 |
| 驱动模型参考 | [open-avc/openavc](https://github.com/open-avc/openavc) | 50 | **MIT** ✅ | 唯一对口的开源 AV 中控。star 少不能依赖，但它的 **YAML 驱动格式**值得直接借鉴 |

### 2.3 只可参考、不可混入（许可证风险）

若这套系统要交付给医院/客户，以下项目的传染性条款会污染你的闭源代码：

| 项目 | License | 风险 |
|---|---|---|
| [kerwincui/FastBee](https://github.com/kerwincui/FastBee) (2.3k) | **AGPL-3.0** | 界面最像截图，但 AGPL 对 SaaS 也传染。只看不抄 |
| [seatsurfing/seatsurfing](https://github.com/seatsurfing/seatsurfing) (313) | **GPL-3.0** | 工位/会议室预约数据模型很好，只读设计 |
| [sagoo-cloud/sagooiot](https://github.com/sagoo-cloud/sagooiot) (880) | LGPL-3.0 | 动态链接可用，静态混入不行 |
| [openremote/openremote](https://github.com/openremote/openremote) (1.9k) | AGPL 类(NOASSERTION) | 自带楼宇+能源+资产建模，理念最近，但许可证要单独谈 |

### 2.4 评估过但不推荐

- **ThingsBoard** (22.4k, Apache-2.0)：生态最大，但为遥测时序数据设计。要做"下发私有指令 + 场景预案"需大改，得不偿失。
- **Home Assistant** (90.2k)：家庭场景，无多租户、无组织架构、无预约、无工单。不适用。
- **ThingsPanel** (572, Apache-2.0) / **unitedrhino/things** (644)：Go 栈，可视化看板不错，但协议扩展弱于 JetLinks。
- 国内 SpringBoot+Vue 会议室预约 demo：只有增删改查，清单要求的 OA/Outlook/Exchange/钉钉/飞书对接、跨天会议、座次预设、占空传感器自动释放全都没有。

## 三、必须自研的部分（开源帮不上忙）

按工作量排序：

1. **设备驱动层**——每个型号一个驱动，指令码表要向 EMeta 或设备厂商索取。
   建议做成"驱动 = 配置文件"（参考 OpenAVC 的 YAML），而非每台设备写一遍 Java。
   最少需要：串口服务器透传、网络继电器(Modbus-TCP)、时序电源(RS232+网络，含电压电流回读)、
   红外扩展器、HDMI 矩阵、数字会议主机、投影/显示(PJLink 可复用开源实现)。
2. **场景/预案引擎**——"场景控制""一键全开/全关"、会议开始前自动调用场景、结束自动关闭。
   含设备上电顺序与延时（时序电源每路延时 1–999 秒，投影机必须最后关）。
3. **空间层级 + 预约日程**——截图里的甘特图日程、冲突检测、空间占比统计（周预约时长÷可预订总时长×40h）。
4. **总平台↔分平台热备同步**（清单 ¥9,000 那项）——切换时间要求 <1.2s。
5. **巡检**——自动巡检（对比设备实测状态与系统状态）+ 人工扫码巡检 + 巡检报告。
6. **AI 速记**——清单里**没有**这项，是截图站点独有的。Whisper 系可直接用。

## 四、清单与截图的差异（重要）

截图那个 C-AIoT 站点的范围 **大于** 这份清单：

| 截图有 | 清单有对应条款？ |
|---|---|
| 空间展示、设备列表、告警中心、消息中心、资产管理、运维巡检、工单管理、主机状态 | ✅ 有 |
| 能源管理 | ✅ 有（时序电源电压电流上传 + 能耗监测） |
| 会议预约、预约日程 | ✅ 有（EMeta-MMS，63 条） |
| **AI 速记** | ❌ 无 |
| **系统引擎** | ❌ 无（推测是规则/场景引擎配置页） |
| 空间视频预览 | ✅ 有（第 8 条"实时查看并控制视频流画面"） |

反过来，清单里有而截图里没看到的：**信息发布对接**、**电子桌牌/门口标牌**、
**无纸化会议（投影申请、流媒体编码、升降终端）**、**网络拓扑图设计器**、**1:1 平面仿真模型**。
