## 0. 范围界定（最重要）

清单共 65 个子系统、计件设备 88,854 件，但**属于本平台的交付物只有第 427–433 共 7 项**。
摄像机、门禁、照明模块、电表由各专业厂商供货实施，本平台的职责是把它们接进来、
看得见、管得住。范围搞错会直接导致报价与工期崩盘。

## 2. 架构约束：三网隔离

清单把信息网络明确分为内网 / 外网 / 专用网三张物理隔离的网（清单 5–44）：

- **内网**：核心 2 套、接入交换机 162 台、AP 728 台。承载医疗业务。
- **外网**：核心 2 套、接入 78 台。承载办公与对外服务。
- **专用网**：核心 2 套、POE 88 台、工业交换机 2 台。承载安防与楼宇自控。

**头号架构决策：平台部署在哪张网。** 被集成设备多在专用网，使用者在内网/外网。
网闸摆渡、双机分侧、专网采集内网展示三种方案的成本与工期相差一个量级。

分层：设备接入层 → 协议适配层 → 数据融合层 → 业务应用层 → 展现层。

协议要求：`RS485/232、API、BACnet、ODBC、OPC、Modbus`（清单 431），
`MQTT、HTTP、Onvif、GB28182` 及私有视频流（清单 428）。

## 4. 功能需求

按交付物拆分，条目均来自清单原文。

- **4.1 综合态势与视频**（427/428）：首页按角色汇总各子系统关键数据（环境、医疗、
  人车通行、能耗、工单、设备）；楼层视频点位图，图标区分类型与在线状态；
  外部报警接入，触发时画面闪烁提醒。
- **4.2 基础信息与台账**（429-7）：空间管理（每房间二维码）、设备台账（每设备二维码、
  批量导入导出、权限分配）、附属设备拓扑关系、空间/使用类型字典。
- **4.3 报修工单**（429-2）：可配置流程引擎、工单列表与详情、按权限控制查看与处理。
- **4.4 维保管理**（429-3）：维保模板（系统-类别-类型）、计划（周/半月/月/季/半年/年）、
  责任班组、外委单位。
- **4.5 巡检管理**（429-4）：设备巡检与设备间巡检、批量或单设备配置、巡检点可排序、
  点类型限「是否/数字/文本」三种、定时推送、排班。
- **4.6 消息中心与告警**（429-5）：规则管理、模板管理、我的消息（可跳详情、在线流程化处理并回填）。
- **4.7 业务报表**（429-6）：工单统计与分布，**导出表头模板化配置**。
- **4.8 系统管理**（429-8）：项目管理、RBAC 角色、用户、无限级部门树、系统日志可回溯。
- **4.9 移动端 APP**（430）：首页推送、扫码查台账与执行任务、**巡检与维保结果支持离线提交**。

### 两条清单没写但必须做的

**二维码是物理入口。** 巡检、维保、报修、盘点四条业务线全靠扫码启动。编码规则、
印制规格、贴附位置必须在设计阶段一次定死——贴到数万件设备上再改，代价无法承受。

**告警必须按 `(设备, 告警码)` 聚合。** 我们在设备模拟中实测：13 条在告故障对应 6,310 次
发生；不聚合的话一台离线设备按 10 秒轮询一小时产生 360 条。以本项目 5,000+ 接入点规模，
告警中心第一天就不可用。建议写入需求并与甲方确认。

而清单 430 原文有「7×24 小时随时随地掌控」——配置与期望不匹配，需澄清。

## 6. 数据模型要点

- **空间树**：院区 → 楼栋 → 楼层 → 房间，每房间一码一类型。
- **设备台账**：设备↔空间多对一，设备↔附属设备拓扑；一码一 SN，含品牌型号供货商、
  启用日期、质保期。
- **点位**：一设备多个可读点/可写点，**可写点必须带权限与二次确认标记**。
- **告警**：按 (设备, 告警码) 聚合，含首次/最后发生、累计次数、等级、处理状态、
  处理人、处理照片、恢复时间。
- **工单 / 维保任务 / 巡检任务**：结构相近生命周期不同，建议共用基础表 + 各自扩展。
- **组织架构**：无限级部门树，班组与外委单位挂其下。

## 7. 实施路径

1. **立刻启动**：基础信息、组织架构与权限、工单/维保/巡检三条业务线。零外部依赖，
   占总工作量最大。
2. **并行推进**：设备模拟器已建成（见 [`模拟器与数据契约.md`](./模拟器与数据契约.md)），
   可在无真实设备时开发验证接入层。
3. **受阻于外部**：13 个子系统实际对接，按「文档到位即开工」滚动排期，不等齐再开始。
4. **最后收口**：大屏与综合态势，依赖前面所有数据源就位。

## 8. 待确认事项

1. **平台部署在哪张网？跨网数据如何流转？**（全项目第一决策点）
2. **变配电、给排水、锅炉、医用气体、物流传输的设备在哪个标段？**（要求集成但不在本清单）
3. **信创要求到什么深度？**（CPU 已国产，OS/数据库/中间件是否同样受限）
4. **等保定级几级？何时测评？**（三级对日志、审计、加密、堡垒机有架构级硬性要求）
5. **SLA、并发规模、遥测数据保留期？**（清单仅定义了日志 ≥2 年）
6. **哪些子系统允许下发控制？需甲方书面确认。**（建议医护对讲与防冲撞柱明确列为只读并写入合同）
7. **二维码编码规则与印制方案？**（四条业务线依赖，返工需重贴数万件设备）
8. **是否需与 HIS / OA / 企业微信对接？**（清单提到组织架构同步与「医院全系统对接」但未指明对象）
