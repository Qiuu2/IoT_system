# 接入层设计与开工指引（乙）

> 契约：[`contracts/ingest-api.yaml`](../contracts/ingest-api.yaml)
> 代码：[`gateway/`](../gateway/)

## 一、和甲并行的关键：先钉契约，不是先分模块

乙和甲之间只有一条缝：**网关把归一化后的数据推给平台，平台把控制指令交给网关执行**。
这条缝钉死了，两边就能各写各的，谁也不等谁。

**契约由乙起草，不要等甲给。** 理由是设备侧的现实只有乙知道——点位读写边界、
采集时延、断网补传、指令过期。这些约束如果由平台侧凭空设计，大概率不可实现。
起草完拿给甲评审，比反过来快得多。

三条并行铁律：

1. **先给甲一个能跑的 mock。** `gateway/mock_platform.py` 是平台侧的 mock，
   乙用它自测；反过来甲需要的是网关侧 mock 数据——直接把 `--platform` 指向甲的开发环境，
   甲那边立刻就有真实结构的数据流，不用等真设备。
2. **契约变更走版本，不走口头。** 改字段先改 `contracts/ingest-api.yaml`，
   再改 `gateway/model.py`。顺序反了两边必漂移。
3. **空间树的主数据在甲那边。** 网关只报 `space_ref`（现场位号），
   由平台完成映射。乙不要自己维护一套空间树，否则两边对不上。

## 二、方向约定与网络形态

| 方向 | 内容 | 发起方 |
|---|---|---|
| 上行 | 注册、遥测、事件、心跳 | 网关 POST |
| 下行 | 控制指令 | **网关轮询拉取** |

下行也让网关拉，是因为本项目三网物理隔离（招标清单 5–44 行）。设备多在专用网，
平台可能在另一侧。网关只发起出站连接，可以适配单向网闸、防火墙单向放行等多种形态；
若改成平台反向调用网关，一旦网闸是单向的，控制链路直接不通。

**这也是 PRD 里 Q1 未决时唯一稳妥的设计**——不管最终选哪种网络方案，这套都能落。

## 四、几个已验证的设计取向

**写权限由驱动声明，网关侧兜底拒绝。**
点位的 `kind` 写在驱动 JSON 里，`commander.py` 直接拒绝越权指令，不依赖平台自觉。
医院场景下医护对讲、防冲撞柱被误控是人身安全问题，判断必须放在离设备最近的地方。
实测：对只读点位下发 → `rejected`，附拒绝理由。

**指令带过期时间。**
网关断网数小时后恢复，不应把早已失去意义的开关指令补发到现场。
实测：过期指令 → `expired`，不下发。

**能回读的必须回读。**
Modbus 写线圈后立即读回，`readback` 随执行结果一并上报。实测 `readback=True`。

**上行数据先落盘再发送。**
一批一文件、写临时文件再原子改名。实测：平台停机期间队列 2→4→6→8 递增，
恢复后一轮补发 14 个批次清空，1404 条读数全部补回，无丢失。

**采集完全由驱动的 `probe` 段驱动，采集器不对任何型号特判。**
早期把解析写死在采集器里，导致红外扩展器的 `STAT 0` 被当成「电压 0.0V」。
声明式配置从结构上避免这类 bug。

## 五、驱动开发工作流

13 个子系统是乙的工作量大头。把「写驱动」变成「填声明 + 过检查」：

1. 复制一份现有驱动 JSON 作模板
2. 填 `transport` / `probe` / `points` / **`confidence`**
3. `python3 gateway/conformance.py <驱动名>` 通过
4. 在 `sim/device.py` 加一个对应的假设备，先在模拟环境跑通
5. 拿到真设备后，只改 `collect.py` 的协议客户端与 `commands` 段

**`confidence` 必须如实填。** 一致性检查会对「指令集为 guessed 却声明了可写点位」
发出提示——这类点位在拿到厂商文档前不应在生产环境放开下发。

## 六、本周就能开工的事（不依赖硬件与厂商）

1. **契约评审**——把 `contracts/ingest-api.yaml` 给甲，一次性对齐字段与语义。
2. **把 mock 指向甲的开发环境**——甲立刻有真实结构的数据流可用。
3. **标准协议先行**——Modbus、BACnet、Onvif 是公开标准，不需要任何厂商文档，
   现在就能写。清单里 BA（1360 点）、能耗（357 表具）、视频（1663 摄像机）
   都走标准协议，这三个是接入量最大的三块。
4. **补齐模拟设备**——现有模拟器只覆盖会议中控。按清单补 BA、照明、能耗、门禁的
   假设备，后续 13 个系统的对接就都有靶子可打。
5. **催接口文档**——把 13 个厂商的接口文档做成台账，标注责任人与承诺日期，
   进周报。这件事越早开始越好，它决定 P2 的实际工期。

## 七、跑起来

```bash
# 三个终端
cd sim && python3 run.py            # 模拟设备（156 台，走真实 TCP / Modbus-TCP）
python3 gateway/mock_platform.py    # 平台 mock
python3 gateway/main.py             # 网关

# 看平台侧收到什么
curl -s localhost:8090/api/v1/_debug/state | python3 -m json.tool

# 下发一条控制指令自测
curl -X POST localhost:8090/api/v1/_debug/command \
  -H 'Content-Type: application/json' \
  -d '{"device_id":"GW-01-DEV-0021","point_key":"ch3","value":true}'

# 驱动一致性检查
python3 gateway/conformance.py
```

对接甲的真实平台时，只需 `python3 gateway/main.py --platform http://<甲的地址>/api/v1`，
网关代码一行不改。
